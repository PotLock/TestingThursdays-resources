# Testing Thursdays Resources

Testing Thursdays is an open-source founder acceleration system for helping builders move from assumptions to real market evidence faster.

The goal is not to maximize meetings, features, or feedback volume. The goal is to help founders reach the next meaningful market milestone safely and quickly.

## Core loop

**DEFINE END STATE → IDENTIFY CONSTRAINT → TEST / BUILD / SELL → SHIP → REACH USERS → MEASURE → LEARN → DECIDE → REPEAT**

## Use this repository when you need to

- validate an idea before overbuilding it;
- get an MVP in front of users faster;
- improve QA and usability testing;
- prepare a product for production;
- find first users or customers;
- improve activation, retention, pricing, or distribution;
- run founder accountability and breakout sessions;
- facilitate a Testing Thursday chapter or similar founder lab;
- use AI tools to audit products, codebases, screenshots, tests, and feedback;
- know what **not** to work on yet.

## Principles

1. Evidence beats opinions.
2. Founders should define success before asking for feedback.
3. Humans test human problems; machines should catch machine problems where possible.
4. Observe before prescribing.
5. Give testers goals, not click instructions.
6. Every serious bug should improve the regression suite.
7. Separate launch blockers from post-launch polish.
8. Every week ends with a concrete commitment and deadline.
9. Return with evidence, not a vague status update.
10. Installing tools is not progress; learning, shipping, selling, and retaining users are progress.
11. Distribution begins before the product feels finished.
12. Scale only after the core value and operating loop are understood.
13. The safest useful exposure level is usually better than indefinite private building.
14. AI can improve the testing process; AI is not a substitute for real users.
15. Higher-risk products require stricter launch and expert-review gates.
