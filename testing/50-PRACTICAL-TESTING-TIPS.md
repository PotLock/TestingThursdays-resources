# 50 Practical Testing Tips

1. Define the core action before testing.
2. Define success before testing.
3. Identify the target user.
4. Write the expected journey.
5. Test the riskiest assumption early.
6. Identify what absolutely must work.
7. Test realistic context and device conditions.
8. Test value proposition as well as mechanics.
9. Do not explain the interface.
10. Give goals, not click instructions.
11. Ask testers to think aloud.
12. Let testers remain stuck long enough to learn from it.
13. Do not defend the product.
14. Avoid leading questions.
15. Ask what the tester expected to happen.
16. Watch behavior before opinions.
17. Capture exact user language where useful.
18. Ask what they normally use instead.
19. Ask what would stop them continuing.
20. Ask why they would return.
21. Try empty input.
22. Try very long input.
23. Try unusual but valid characters where relevant.
24. Tap consequential buttons more than once in safe test environments.
25. Press Back during workflows.
26. Refresh during a workflow.
27. Restart the app.
28. Test network interruption safely.
29. Deny optional permissions.
30. Test expired sessions.
31. Test first-time users.
32. Test returning users.
33. Test zero-data states.
34. Test high-data states.
35. Test failure states.
36. Test partially completed states.
37. Test canceled states.
38. Test duplicate actions.
39. Test different roles/permissions.
40. Test persisted state after an update.
41. Test the smallest supported screen.
42. Test slower devices when relevant.
43. Test slower connectivity when relevant.
44. Increase text size.
45. Open the keyboard on forms.
46. Test orientation if supported.
47. Test supported display modes.
48. Use real devices where practical.
49. Test production-like configuration without exposing sensitive production data.
50. Have someone who did not build the product test it.
